# ネットワークモニターサーバ 要件定義

## 1. 文書情報
- 文書名: ネットワークモニターサーバ 要件定義
- 作成日: 2026-03-16
- 対象プロジェクト: `net-monitor-mini`
- 文書目的: 初期リリースで実現する機能要件と、今後の機能追加を見据えた基本方針を定義する

## 2. 背景
- Windows PC 上で常時稼働するネットワーク監視ソフトを構築する
- 初期機能として、特定 PC に対する定期 ping 監視と結果のグラフ表示を実現する
- 将来的に監視対象、監視方式、通知、可視化項目を拡張できる構造を前提とする

## 3. システムの目的
- 指定した監視対象 PC の疎通状態を継続的に確認できること
- ping の成功/失敗および応答時間の変化を時系列で確認できること
- 後続の監視機能追加時に既存機能への影響を最小化できること

## 4. 対象範囲

### 4.1 初期リリースの対象
- Windows PC 上で常時稼働する監視アプリケーション
- 最大 10 台の監視対象 PC に対する ping 実行
- 5 分ごとに 3 回連続で ping を実行する定期監視
- 実行結果の保存
- 保存結果のグラフ表示

### 4.2 初期リリースでは対象外
- メール、チャット、ポップアップなどの通知
- ping 以外の監視方式
- リモート端末からの操作
- 複数ユーザー管理
- 詳細な権限管理

## 5. 利用者
- 自社内または個人環境でネットワーク状態を確認したい運用担当者
- 常時起動 PC 上で簡易監視を行いたい利用者

## 6. 前提条件
- 動作環境は Windows PC とする
- 監視対象 PC は IP アドレスまたはホスト名で指定できるものとする
- 監視元 PC から OS 標準の ping 実行が可能であることを前提とする
- 常時稼働を前提とするため、アプリケーションは長時間運転で安定動作する必要がある

## 7. 機能要件

### 7.1 監視設定
- 監視対象を設定できること
- 監視対象ごとに以下を保持できること
  - 識別名
  - IP アドレスまたはホスト名
  - 監視有効/無効
- 初期値として、ping 間隔は 5 分、1 回の監視あたりの実行回数は 3 回とする
- 将来的に監視間隔や回数を設定可能に拡張しやすい構造とする

### 7.2 ping 実行
- 監視スケジュールに従い、5 分ごとに対象 PC へ ping を 3 回実行すること
- 各 ping の結果として少なくとも以下を取得すること
  - 実行日時
  - 監視対象
  - 成功/失敗
  - 応答時間
- 3 回の結果を 1 監視サイクルとして扱えること
- タイムアウトや名前解決失敗など、ping 実行失敗を判別できること

### 7.3 データ保存
- ping 実行結果を継続的に保存できること
- 保存データは、少なくともグラフ表示に必要な時系列情報を保持すること
- 将来の機能追加に備え、監視種別が増えても保存形式を拡張しやすいこと

### 7.4 可視化
- ping 結果を時系列グラフで表示できること
- 少なくとも以下の可視化に対応すること
  - 応答時間の推移
  - 成功/失敗の判別
- 監視対象ごとに表示を切り替えられること
- 直近 1 週間の履歴を確認できること
- グラフの X 軸目盛りは `dd HH` 形式で表示すること

### 7.5 常時稼働
- 起動後、監視処理を自動継続できること
- 一時的な監視失敗や対象停止があっても、アプリケーション全体は停止しないこと
- ログまたは保存データから、後で監視状況を追跡できること

## 8. 非機能要件

### 8.1 拡張性
- 機能追加しやすいモジュール構成とすること
- 少なくとも以下の責務を分離できる構造を前提とすること
  - 監視実行
  - スケジュール管理
  - データ保存
  - グラフ表示
  - 設定管理
- 将来的に以下を追加しやすいこと
  - 監視方式追加
  - 通知機能
  - 集計機能
  - 監視対象の増加

### 8.2 保守性
- 設定値、監視ロジック、表示ロジックを分離すること
- 主要処理に対してテストしやすい構造とすること
- 障害時に原因追跡できるログ設計を考慮すること

### 8.3 性能
- 初期リリースでは小規模利用を対象とする
- 少数台の監視対象に対して、5 分ごとの監視を安定実行できること
- 常駐動作において CPU・メモリ消費が過大にならないこと

### 8.4 可用性
- 長時間起動に耐えること
- 一部監視対象の失敗が他対象の監視に波及しないこと

## 9. データ要件
- 監視結果は時系列で蓄積する
- 1 レコード単位で、監視対象、実行日時、試行番号、成功/失敗、応答時間、補足情報を保持できること
- 将来、監視種別ごとの追加項目を持てる拡張余地を持たせること

## 10. 想定画面要件
- 初期リリースでは最低限、以下の画面または表示機能を持つこと
  - 監視対象一覧
  - 監視状態確認
  - グラフ表示
- 表示は、監視状態を直感的に確認しやすいこと
- 詳細 UI 設計は別途設計書で定義する

## 11. 想定アーキテクチャ方針
- 本プロジェクトは、将来の拡張を考慮し、機能単位で責務分離した構成を採用する
- 初期段階から、以下のような論理分割を前提とする
  - `monitoring`: ping など監視処理
  - `scheduler`: 定期実行制御
  - `storage`: 結果保存
  - `visualization`: グラフ表示
  - `config`: 設定管理
- 実装技術の最終決定は設計フェーズで行うが、AGENTS.md の方針に従い、Windows 向け常駐監視とローカル UI をどう両立するかを含めて検討する

## 12. 今後の追加候補
- 監視対象の複数台管理
- HTTP/TCP ポート監視
- 閾値超過時の通知
- CSV エクスポート
- 日次、週次レポート
- 自動起動設定
- Web UI またはデスクトップ UI の強化

## 13. 未確定事項
- UI 方式をデスクトップアプリにするか、ローカル Web UI にするか
- 保存先をファイルベースにするか、ローカル DB にするか
- 常駐方式を通常アプリにするか、Windows サービス化も視野に入れるか
- グラフの初期表示期間、更新頻度、保持期間
- 監視対象の初期最大件数
